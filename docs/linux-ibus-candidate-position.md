# Muffin 0.7.9：IBus 候选框定位问题排查

记录日期：2026-10-31。

**后续状态：** 已完成 `0.7.9-1+ibus2` 位置同步修复及重新打包。详见 [ibus2 修复记录](linux-ibus-position-fix-ibus2.md)。以下保留此前的排查过程与当时状态。

## 1. 用户反馈与本次范围

用户安装 `muffin_0.7.9-1+ibus1_amd64.deb` 后确认已能输入中文，但候选框不贴近输入光标、不随光标移动，而是停留在软件界面底部；窗口最大化或全屏时更容易出现。

本次定位问题原因，没有替换系统已安装程序、修改输入法配置或生成新的升级包。

## 2. 环境

- Debian 13 amd64，GNOME X11，ibus-rime。
- 已安装 Muffin 包版本：`0.7.9-1+ibus1`。
- 应用私有 Qt：6.11.1。
- GNOME `text-scaling-factor`：1.1。
- 排查开始时未发现正在运行的 Muffin 主进程。

## 3. 源码检查

### 3.1 有光标查询，但缺少主动更新通知

`src/editor/EditorView.cpp` 中的 `EditorView::inputMethodQuery(Qt::ImCursorRectangle)` 通过 `effectiveCursorRect()` 获取文档光标矩形，并减去垂直滚动偏移后返回。

但检查以下编辑器实现，没有找到 `updateMicroFocus()` 或 `QInputMethod::update(...)` 调用：

- `src/editor/EditorView.cpp`
- `src/editor/EditorViewViewport.cpp`
- `src/editor/EditorViewPaint.cpp`
- `src/editor/VirtualSourceEdit.cpp`

光标移动、预编辑变化、滚动及重排时，编辑器更新了自身绘制，但未主动通知 Qt 平台输入法刷新定位。

**能查询到新位置，不等于平台输入法已收到新位置。**

### 3.2 与上一版修复的区别

上一版补齐 IBus 插件和 Qt D-Bus 库，解决的是“输入法不能接入”。候选框位置同步属于编辑器与输入法之间的运行时通知问题，上一版未改动这部分编辑器逻辑。

## 4. 实际运行诊断

### 方法

使用与已安装程序匹配的 Qt 6.11.1 SDK 头文件及其私有运行库，编译临时诊断库。在独立配置、独立临时 Markdown 文件的测试实例中加载它：

- 诊断库：`local/libime-position-probe.so`
- 诊断源码：`local/ime-position-probe.cpp`
- 测试目录：`local/ime-position-test/`
- 完整日志：`local/ime-position-test/probe.log`

诊断在应用进程内模拟光标移动并切换普通、最大化、全屏状态，查询编辑器矩形和 Qt 输入法矩形；不向其他应用发送全局模拟按键，也不打开用户笔记。

诊断库只对测试进程通过 `LD_PRELOAD` 加载，没有加入系统启动器或安装目录。测试进程已退出。

### 观测结果

以下为逻辑坐标，用于比较各阶段的位置变化，不应直接当作屏幕物理像素坐标：

| 阶段 | 编辑器返回的光标矩形 | Qt 输入法查询得到的窗口内矩形 |
|---|---|---|
| 普通窗口 | `(493, 45, 1, 22)` | `(493, 71, 1, 22)` |
| 向右移动后 | `(518, 45, 1, 22)` | `(518, 71, 1, 22)` |
| 最大化后 | `(791, 45, 1, 22)` | `(791, 71, 1, 22)` |
| 全屏后 | `(813, 45, 1, 22)` | `(813, 71, 1, 22)` |

两组坐标的纵向差为编辑器相对主窗口的 26 像素偏移，与运行时 `inputItemTransform()` 一致。当前测试中 viewport 相对编辑器的偏移为 `(0, 0)`。

这些结果表明：测试中的编辑器能够查询到随光标移动、窗口尺寸变化而改变的合理坐标，并非始终返回底部位置。

随后在每个阶段显式调用：

```cpp
QGuiApplication::inputMethod()->update(Qt::ImQueryAll);
```

Qt IBus 日志立即出现对应的新定位输出，例如：

```text
PROBE normal-before-update ...
qt.qpa.input.methods: microFocus QRect(1361,392 1x24)
PROBE normal-after-update ...

PROBE fullscreen-before-update ...
qt.qpa.input.methods: microFocus QRect(889,78 1x24)
PROBE fullscreen-after-update ...
```

`microFocus` 是 Qt IBus 插件发送光标位置的日志；其屏幕坐标考虑了窗口位置和缩放，因此与表中的逻辑局部坐标不同。

本次日志中这些定位发送由显式更新调用触发，与“应用有正确查询结果，却缺少更新通知”的源码检查结果相符。

## 5. 结论

已确认存在一个能解释用户现象的编辑器缺陷：**光标定位信息的主动同步通知缺失**。IBus 插件已能连接，但编辑器光标、预编辑布局或窗口状态变化后，没有可靠地促使平台输入法重新定位候选框。

窗口最大化和全屏会触发内容重排及窗口坐标变化，缺少通知时更容易暴露定位不同步的问题。这不是当前证据下需要优先修改的 Rime 配置问题。

## 6. 建议修复位置与验证要求

后续修复应在编辑器层进行：

1. 光标和选区变化后更新输入法状态。
2. 预编辑字符串及其光标变化后，在布局稳定时更新候选框位置。
3. 垂直滚动、代码块水平滚动、窗口尺寸和视图重排后更新位置。
4. 检查焦点切换、源码模式，以及 viewport 坐标到焦点控件坐标的转换。
5. 合并同一事件循环中的重复更新，避免在布局尚未稳定时发送旧坐标，或每次绘制都产生无必要的 D-Bus 调用。

可使用 `QWidget::updateMicroFocus()` 或适当的 `QInputMethod::update(...)` 通知；应结合实际焦点和最终光标几何调用，而不是更改输入法全局偏移。

## 7. 尚未完成的验证

- 本次没有发布或安装候选框定位修复版。
- 没有测量实际可见候选面板相对光标的像素距离；目前确认的是查询坐标与定位通知链路。
- 仍需在真正的 ibus-rime 预编辑/选词过程中验证普通窗口、最大化、全屏、滚动及缩放，并检查预编辑光标换行。
- 源码模式、复杂表格、代码块水平滚动等情形还需要回归测试。

因此，本记录属于“原因已定位、修复方向已验证”，不应理解为已安装程序中的候选框问题已经修复。
