# Muffin 0.7.9：大图只显示左侧的修复记录（ibus4）

日期：2026-10-31。

## 1. 交付

- 安装包：下载目录中的 `muffin_0.7.9-1+ibus4_amd64.deb`。
- 大小：46,710,060 字节，约 44.5 MiB。
- SHA256：`cbbea0607dc704f9d8ec50fad4b5e74046420ac4dd1c92065d158ae0badf4ce6`。
- 可以直接从 ibus3 升级，保留此前高亮和输入法修复。
- 没有执行系统安装，没有改动用户笔记、图片原件、输入法配置或用户主题文件。

## 2. 复现与原因

生成独立的三色测试 PNG：左红、中绿、右蓝，尺寸 2400×600。原 ibus3 在普通、窄窗口、最大化、全屏及缩放状态下，都无法显示右端蓝色区域；截图确认仅露出左侧或少量中部。

默认基础样式和 GitHub 等主题没有为图片提供最大显示宽度。`InlineLayout::buildImageAtoms()` 按图片自然尺寸及编辑器缩放计算尺寸，现有 `cssReplacedSize()` 支持等比约束，但没有 `max-width` 时不会自动限制到正文宽度。超出的部分被编辑区裁剪，且编辑器没有横向滚动条。

以测试图和 120% 缩放为例，原尺寸会得到 2880×720 的显示需求，而正文只有约 960 宽，因此大部分内容在可见区域之外。问题并非图片损坏或插入时被裁掉。

## 3. 修复

在 `resources/themes/document-base.css` 增加基础规则：

```css
img { max-width: 100%; height: auto; }
```

效果：

- 图片最大宽度不超过其正文容器。
- 高度按原始比例计算，不压扁或拉长。
- 使用 `max-width` 而不是 `width:100%`，不会把小图强制拉满正文。
- 全局编辑器缩放仍正常生效。例如 160×80 小图在 120% 缩放下显示为 192×96，并非完全禁止随编辑器缩放。
- 竖长图保持比例，超过窗口高度的部分通过正常纵向滚动查看，不强制压缩到一屏。
- 主题或行内显式样式仍可覆盖默认值；自定义 50% 最大宽度和 200px 宽度均做了验证。

保留原高亮规则：

```css
mark { background-color: #fff173; }
```

没有改动图片文件尺寸、像素数据、Markdown 内容、解析算法或输入法实现。

## 4. 本地打包方式

继续采用官方编辑器二进制及受校验的基础 CSS 数据补丁，不完整重编译编辑器。

从固定 SHA256 的原始发行包解出副本，确认完整原始基础 CSS 恰好出现一次后，将开头 77 字节的注释替换为两条紧凑规则及空白：

```css
mark{background:#fff173}img{max-width:100%;height:auto}
```

紧凑规则长 55 字节，放入注释原占位区域后，文件大小、字符串长度、所有 ELF 地址和机器指令不变；补丁区域外逐字节相同。

```text
文件：libMuffinUi.so
大小：43,799,208 字节（不变）
CSS 注释偏移：10,921,568
允许修改区域：77 字节
相对官方原库的实际不同字节：73

原库 SHA256：
a1c3fe544698f7a626f90c0eed7b81c34e1e506d1952ce3275e9b940165c3776

ibus4 库 SHA256：
883bad31b7bd113d8cd2e020fd0aa386a0a76de58e5b219f4c83e21c7cfe74a5
```

对比 ibus3 全部应用运行文件，仅 `libMuffinUi.so` 改变；主程序、解析核心、Qt 库、IBus 插件和候选框定位适配插件保持字节一致。

打包器保留原有哈希、唯一匹配、等长和重复补丁拒绝校验，并新增“图片规则缺失时拒绝补丁”的单元测试。元数据保留兼容键名 `highlight_base_css_patch`，其中新增 `image_rule` 和 `embedded_rules`。完整基础 CSS 随包保存在 `/usr/share/doc/muffin/document-base.css`。

## 5. 图片验证

### 测试方法

新增：

```text
tests/packaging/ImageFitProbe.cpp
tests/packaging/run_image_fit_acceptance.py
```

使用实际安装包解出的程序、独立配置及生成的 PNG，不读取用户图片。Qt 测试驱动抓取编辑区预览，并将整个图片所在块绘制到独立画布，检查：

- 左、中、右三色区域是否都存在且比例均衡，避免把裁剪误判成缩放。
- 完整图像颜色边界的宽高比是否与源图一致。
- 小图是否仍按用户缩放倍数显示，而不是拉满正文。
- 改变窗口宽度后、最大化/全屏后，以及 200%→80%→120% 缩放后是否重新适配。
- 测试前后 PNG 和 Markdown 的 SHA256 是否不变。

截图预览最长边不超过 1600 像素，原始生成图片保持不变。已实际读取修复前和修复后截图，确认不只是几何日志发生变化。

### 测试修正说明

探索测试中有两处测试预期/夹具需要修正，原日志保留：

## 7. 安装

先保存笔记，退出所有 Muffin 窗口，进入安装包所在目录后直接升级，无需卸载：

```bash
sudo apt install ./muffin_0.7.9-1+ibus4_amd64.deb
```

重新启动后，原有笔记中的普通大图会按正文宽度显示，无需重新插入、裁剪或转换图片。若笔记/自定义主题显式写了允许超宽的样式，它仍可能覆盖此默认规则，应单独检查。

## 8. 重建与范围

在源码目录运行；可通过环境变量 `PYTHON` 指定现有 Python 解释器，未指定时使用 `python3`：

```bash
${PYTHON:-python3} scripts/package_linux_deb.py \
  --bundle-archive local/downloads/Muffin-v0.7.9-linux-x64.tar.gz \
  --qtbase-archive local/downloads/qtbase-6.11.1.7z \
  --qt-sdk local/qt-sdk \
  --output-dir packages/ibus4-rebuilt
```

只测试了本机 Debian 13 amd64、GNOME X11，以及 Qt 离屏渲染。没有覆盖所有远程图片、表格图片、特殊显式宽高规则、图片格式、Wayland 或其他架构，不能宣称所有图片边界情形均已验证。
